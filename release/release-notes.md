- v1.9.1 is a patch on the 1.9 line that completes the standalone-binary release lane: every GitHub release now attaches the sqlite-vec native extension as a per-platform archive (`sqlite-vec-<os>-<arch>.tar.gz`) next to the compiled binaries, so a directly-downloaded binary can restore the semantic memory vector index by co-locating the addon.
- Each addon archive carries the exact `lib/sqlite-vec-<os>-<arch>/vec0.<suffix>` layout the runtime resolves, so it extracts in place beside the binary with no renaming, and every archive is checksummed in `SHA256SUMS.txt` under the same missing-entry-fatal rule the platform binaries already use.
- The release build now fetches each target platform's sqlite-vec addon from the npm registry during cross-target builds, so all four platform addons ship regardless of which host built them instead of only the build host's native one.
- README and the release docs explain how to place the addon next to a downloaded binary and confirm it with the `memory vector status` command, which reports `available: yes` once the addon is co-located.
- macOS behavior is documented plainly: the system SQLite on macOS refuses to load extensions, so the darwin addon archives ship for parity but the vector index stays unavailable there and memory search falls back to literal matching. This is a platform limitation, not a packaging defect.
- No change to the Bun/npm install path or to your conversations, memory, skills, routines, or operator confirmation gates; this release only adds the standalone-binary addon assets and the docs that describe them.
