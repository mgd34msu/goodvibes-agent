- Your profile is now something you read and correct yourself. `/owner-profile` shows what the Agent knows about you, looks one person up by name, traces where a fact came from, corrects one, or forgets one. A line is named by the words in it rather than by its position, so editing the file while a correction is in flight cannot take out the wrong line. The same profile is on the workspace screen, and the Agent can consult it mid-turn instead of working from whatever it happened to be told this session.
- Payment details are entered at the terminal. `/payments` takes the card — number, expiry, CVV, cardholder name, each typed masked — and the billing and shipping addresses. Card material is never shown back and never written into a settings file: it goes to the daemon's own secret store, because the daemon is the process that completes an unattended purchase with every window closed. Budgets, delivery tier, approval and veto windows and the CVV trade-off are in Settings > Payments, where an amount is typed the way you would say it ("19.99") and stored exactly.
- An action that reaches outside this machine asks you first when what it is about to send derives from something someone else wrote. A web page it read for you, a message that arrived, a document, and now a subscribed calendar feed all carry that mark, and it is followed through to the moment of sending rather than checked once at the door. Your own words never trigger it — mail you asked for goes out without a prompt.
- Startup now says when a program on your PATH shadows one the Agent expects to run, and when a service it depends on is not reachable, instead of failing later with an error about something unrelated.
- Fixed: a credential typed into settings was filed where only this program could read it. Scheduled work and inbound messages run with no terminal open, so they found nothing and reported the integration as unavailable while the settings screen showed it configured. Credentials now land in the tier the daemon actually reads.
- Fixed: a support bundle would have carried a card number in the clear. The rule deciding what to hide matched words like "token" and "password" at the end of a setting's name, and none of the four card fields ends in a word on that list. Card material is now declared sensitive by name rather than guessed at.
- Fixed: a settings listing that had been cut off said nothing about it. The catalog stopped at a fixed 500 entries while the list of settings had grown past that, so a real setting past the cut read as a setting that does not exist. The ceiling is now well clear of the catalog, and any listing that returns fewer than matched says so and says how to ask for the rest.
- Asked what it can do — reach Gmail, a calendar, a browser — the Agent answers from its own live runtime and says which build is answering, rather than from a search over the source tree, which describes a repository and not the program you are talking to.
- Updated the bundled GoodVibes platform runtime to 1.19.1, which carries the calendar-ingest, payments and owner-approval support behind these notes.
