- **BREAKING**: this build declares a daemon build floor of 1.28.0, and a daemon below it is REFUSED, not merely flagged. The daemon is its own product, with its own repository, package and release line, separate from the embedded topology this Agent shipped and updated alongside itself before that split, and a daemon build below 1.28.0 belongs to that earlier topology — it answers some of the verbs this build depends on and not others, so adopting it produces a half-working Agent where one call returns 404 and reads as a broken feature rather than as an old daemon. On each adoption attempt this Agent reads the daemon's own build off `/status`; below the floor it does not adopt the daemon at all. Concretely, that means the memory spine keeps using its local store instead of routing over the wire, the inbound continuation dispatch never binds, and every daemon-dependent path behaves exactly as it does when no daemon is configured. The first time a below-floor daemon is observed, one system message names both versions: "[Connected host] The daemon at <address> is running build <version>; this client requires 1.28.0 or newer — update the daemon." The daemon updates itself automatically, on its own hourly cycle and at the next idle restart, so the ordinary path needs no action; if it has not updated on its own, update the owning GoodVibes host directly, then restart it. No restart of the Agent is needed once the daemon is current — the floor is re-checked on the next adoption attempt and the daemon is adopted then.
- Changed: this Agent no longer composes any daemon-grade service — it is a pure client of the standalone daemon. The in-process pairing-token manager is gone; a paired phone reaches this Agent's device tools through the daemon's own verbs. An approval ask is raised on the daemon, with this process as one possible answerer, and the approvals panel renders the daemon's record rather than a local-only broker. Settings and credentials written here now go to the daemon over `config.set` and `credentials.set`/`delete`, so scheduled work and inbound channel handling — which run with no terminal open — see the same value this process does.
- Added: the Agent can join, steer, and watch a conversation the daemon is hosting, not only ones running in this process, over the same session verbs used for a local run. With `hostedSessions.promoteInboundConversations` on, the first message of an inbound channel conversation creates a daemon-hosted session and every later message steers into it; the setting ships off, and a daemon that cannot take the handoff falls back to answering here instead of losing the message.
- Changed: the unified inbox reads the daemon's own inbound feed, folding provider messages into the same list as deliveries, surface messages and route bindings, with an honest per-provider reason — refused, unreachable, or no token — when there is none. Composed drafts and channel-to-profile routing assignments now sync to the daemon's own stores, kept locally as pending with a receipt when the daemon cannot be reached, and offered again later.
- Changed: the activity sidebar and `/tasks` now show work the daemon is running that this process did not start — scheduled jobs, hosted sessions, other-surface work — labeled as running elsewhere and unioned with what this process runs itself. Local rows win on a shared id, and a daemon that cannot answer keeps the last rows it gave.
- Fixed: a rewind point can now reach a turn from before the most recent resume. Turn anchors persist to a sidecar beside the session's transcript and reload on `/session resume`, which reports how many rewind points came back; a bounded sweep reclaims stale sidecars at startup and discloses what it removed.
- Changed: no Google or Microsoft OAuth client id ships with this product. Connecting a calendar requires the operator to register their own app with the provider and set the client id under the named key; until then, `/calendar connect` refuses with a message naming the exact key to set.
- Changed: the `daemon.embedInProcess` setting is gone, since this Agent never spawned or embedded a daemon of its own — it only ever adopts one already running. `daemon.enabled` is unaffected and keeps its real meaning.
- Changed: the bundled GoodVibes platform runtime is 2.0.0.
